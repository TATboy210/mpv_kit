# Vulkan-path golden trace of the ring fallback after a resize
# (video_renderer_golden_vk_fallback.cc, harness in renderer_harness.h).
#
# Same format as golden/vk.txt: one [scenario] per section, one expected
# line per line; lines starting with '#' are comments. Serials number the
# images FakeVulkanInterop created in this scenario, in CreateImage order
# from 1. `<device>` stands for the runner's Vulkan device name.
# `acquire index=-1 ... serial=none` is an AcquireFront with no front frame.
# `log ...` lines are the renderer's shared-image allocation-failure
# diagnostics, collected after teardown.

# Latency 4 (ring 8): four 64x36 frames, the last one (serial 4) taken by
# the compositor. The resize to 32x18 retires serial 4 and frees the rest
# of the old ring; the 6th CreateImage of the new ring of 8 fails, which
# frees the five new images and the retired serial 4. The fallback ring of
# 5 (quarantine 2) succeeds. Until its first frame is published
# AcquireFront has nothing to show (serial 4 is gone, it must not be handed
# out); then the new ring rotates under quarantine 2. Every image is
# destroyed exactly once, and the log names ring 8 as the one that failed.
