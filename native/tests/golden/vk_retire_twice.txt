# Vulkan-path golden trace of a resize that follows a resize without a frame
# (video_renderer_golden_vk_retire_twice.cc, harness in renderer_harness.h).
#
# Same format as golden/vk.txt: one [scenario] per section, one expected
# line per line; lines starting with '#' are comments. Serials number the
# images FakeVulkanInterop created in this scenario, in CreateImage order
# from 1. `<device>` stands for the runner's Vulkan device name.
# `acquire index=-1 ... serial=none` is an AcquireFront with no front frame;
# index -2 is the previous generation's retired front.

# Latency 2 (ring 6): one 64x36 frame (serial 1) is taken by the
# compositor. The resize to 32x18 retires serial 1 and frees the rest of
# the old ring; the first 32x18 render fails (held in the fake meanwhile),
# so serial 1 is still what AcquireFront shows. The second resize, to
# 48x27, keeps serial 1 alive (kKeepRetiredFront: a resize before any
# new-size frame must not blank the window) and frees the 32x18 ring,
# which was never shown. Until the first 48x27 frame is published serial 1
# stays on screen; then the new ring rotates under quarantine 2 and serial
# 1 is released once the compositor moved quarantine+1 frames past it.
