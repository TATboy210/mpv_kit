# 本文件之外的已证明部分：DRM_DISPLAY_V2 的参数内容、fd 只关闭一次且在最后一次 render_context_free 之后（video_renderer_drm_params_test，fake libmpv + /dev/null）、路径白名单与按设备号查找（临时目录里指向 /dev/null 的符号链接）、无 /dev/dri 时强制 opengl 与默认链安全回落。
项目=GL 后端（vo_gpu + EGL dma-buf）上的真实 VA-API 零拷贝 状态=未验证 原因=hosted 上 EGL render node 解析必然返回无，mpv 的 vaapi 因没有 VADisplay 被跳过；从未有一帧经 vaapi 解码后以 dma-buf EGLImage 进入 Flutter 纹理 能证明它的环境=带 Intel/AMD 集显或独显且装有 Mesa va 驱动的 Linux 桌面（X11 与 Wayland 各一次），日志可见 vaapi interop 加载与 hwdec-current=vaapi
项目=Vulkan gpu-next（libplacebo dma-buf 导入）上的真实 VA-API 零拷贝 状态=未验证 原因=lavapipe 没有 dma-buf 互操作（16-03 记录 vaapi=interop-unavailable），Vulkan 路径的 render node 解析在 hosted 上返回无 能证明它的环境=带支持 VK_EXT_external_memory_dma_buf 与 VK_EXT_image_drm_format_modifier 的 GPU 的 Linux 桌面
项目=P010 与 10-bit 的 dma-buf modifier，以及 GLES 下缺 GL_EXT_texture_norm16 的情况 状态=未验证 原因=没有硬件解码输出，10-bit 采样的 hevc-10bit 在 hosted 上只走软件路径；modifier 协商与 16-bit 纹理导入没有被观测 能证明它的环境=带 VA-API 的 10-bit HEVC 解码硬件（Intel Gen9+ 或 AMD）的 Linux 桌面
项目=真实驱动上的 render node 解析（Mesa 的 EGL_EXT_device_drm_render_node 与 VkPhysicalDeviceDrmPropertiesEXT） 状态=未验证 原因=只在 hosted 上证明了返回无的路径；两个解析器在真实驱动上返回的路径、hasRender 的取值与 open 的权限（用户是否在 render 组、容器是否映射 /dev/dri）没有观测 能证明它的环境=带真实 GPU 的 Linux 桌面，另需一个没有 render 组权限的会话来观察回落
项目=混合 GPU（DRI_PRIME、PRIME offload）下 render node 与 Flutter EGL 设备的匹配 状态=未验证 原因=Vulkan 路径用 Flutter GL 设备 UUID 选出的物理设备的 DRM 属性，GL 路径用 Flutter 自己的 EGLDisplay 的设备；GL 与 Vulkan 两种解析没有互相校验（hosted 上两者都返回无，校验无法被观测），两者指向同一块 GPU 的依据只是 AcceptDevice 的 UUID 匹配 能证明它的环境=带集显与独显的笔记本或双 GPU 台式机，分别以集显和独显渲染 Flutter
项目=NVIDIA 专有驱动（EGL render node 扩展、nvidia-vaapi-driver）与未实现的 GL UUID 回退 状态=未验证 原因=研究 3.5 的第二回退（GL 设备 UUID → Vulkan 物理设备 → DRM 属性）没有实现：缺少 EGL_EXT_device_drm_render_node 的驱动上 GL 后端不传 render node，vaapi 被跳过；NVIDIA 的 vaapi 本就依赖第三方 nvidia-vaapi-driver，两者的行为都没有观测 能证明它的环境=带 NVIDIA 显卡、专有驱动与 nvidia-vaapi-driver 的 Linux 桌面
项目=真实 render node 的 fd 生命周期与 100 轮 create/dispose 的 fd 数 状态=未验证 原因=原生测试只用 /dev/null 的 fd 证明关闭恰好一次且在最后一次 render_context_free 之后；真实 render node 被 libva/驱动在内部 dup 或长期持有的情况、以及长循环下 /proc/self/fd 的计数没有观测 能证明它的环境=带真实 render node 的 Linux 机器上循环创建与销毁控制器 100 次并统计打开的 fd 数
项目=SC3 的「vaapi interop 加载日志可见」 状态=未验证 原因=hosted 上 vaapi 因没有 VADisplay 而跳过（研究 Pitfall 4），日志里没有 interop 加载行，因此不能作为门禁；16-03 的 vaapi= 值只描述 llvmpipe/lavapipe 与无 /dev/dri 的环境 能证明它的环境=带真实 GPU 的 Linux 桌面，mpv 日志含 vaapi 的 Using hardware decoding 与 dmabuf interop 行
