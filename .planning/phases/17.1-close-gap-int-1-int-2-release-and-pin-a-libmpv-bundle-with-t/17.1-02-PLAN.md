<objective>
Fix the masked flutter-plugin Windows failure in its own commit, red-then-green, per locked decision D-05.

Facts (verified while planning, `gh run view --job 124094812213 --log`): the Locate step runs in Git Bash and exports `MPV_KIT_LIBMPV_PATH: /d/a/mpv_kit/mpv_kit/.dart_tool/hooks_runner/shared/mpv_kit_libs/build/v0.1.0-dev.3/windows-x64/lib/libmpv-2.dll`; Windows Dart cannot open that POSIX form, so `controller_channel_test.dart` fails to load ("libmpv is required by CI (MPV_KIT_REQUIRE_LIBMPV) but could not be loaded") and the run reports `7 tests passed, 1 failed.`. The Analyze step has no `shell:`, so on Windows it runs under `pwsh -command ". '{0}'"`, where only the last native command's exit code (the final `flutter analyze` in example) decides the step: the job stays green. Same pattern in runs 40949963646 (job 123715146292) and 40984192897 (job 123831214051).

Fix, both parts required by D-05: (1) the Locate step writes native Windows paths (`cygpath -w`) on Windows runners, for the libmpv file and for the PATH entry (Windows resolves the dependency DLLs through PATH, since LoadLibrary does not search the loaded DLL's own directory); (2) the Analyze step runs under `shell: bash` with one command per line, so any failure fails the job (`bash -e` does not stop on a failing non-final command of an `&&` list, which is why the chains go too).

Red-then-green is proven locally on this Windows host with the real step scripts and the real dev.3 bundle (the bundle CI still downloads until Plan 05 re-pins). No red commit is ever pushed (carried-over rule `red_evidence=local-only`); Plan 03 pushes this commit and its CI gate asserts the green Windows log.

Purpose: the Windows leg becomes a real pinned-bundle gate, which Plan 05 builds on for the forced-d3d11 step.
Output: one local commit touching flutter-plugin.yml only, plus local evidence.
</objective>
