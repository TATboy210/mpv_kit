<objective>
Turn the lifetime guarantees into continuous, failure-driven regression coverage.

Purpose: The phase is only complete when the failure paths are exercised automatically: a throwing listener/hook, a source whose I/O throws, and 1000 create/dispose cycles. This plan proves that Dart's synchronous broadcast dispatch already isolates listener exceptions (a throwing listener surfaces as a zone error while delivery continues), adds the VERIFY-03 failure-injection suite, adds the STAB-01 soak test, and wires both into CI so they cannot rot or silently skip. It corrects the premise that a controller-wrapped `try/catch` can observe a listener throw: `controller.add` does not rethrow listener exceptions, so no production counter is added.

Output: `failure_injection_test.dart`, `lifecycle_test.dart`, conditional `StreamBridge` hardening, and CI/test-config wiring.
</objective>

  <action>
    Make no production change in this task. Dart's synchronous broadcast controllers (`Mpv._events`, the `observeProperty` controllers, and `MpvState._controller`) dispatch each listener through a zone-guarded call: a throwing listener is reported as an uncaught zone error while `controller.add` returns normally. The throw therefore never propagates out of `add`, `_dispatch`/`_onWakeup` keep draining, and later listeners still receive the value. This supersedes the CONCERNS.md premise that a parse/listener exception escapes the wakeup callback: the exception is isolated by the stream, and what is missing is regression coverage, not production isolation. Do not add a `_listenerErrors` list or a `listenerErrorCountForTesting` getter — such a counter would stay at zero and the tests using it would fail. `01-01` already added the `isClosed` guards to `_dispatch`.

    Create `packages/mpv_kit/test/failure_injection_test.dart` with `@Tags(['failure-injection'])`, `@TestOn('vm')` and a `library;` directive, following the header convention in `mpv_test.dart`. Add helpers to create a `Player`/`Mpv` with `vo=null`, `ao=null`, `idle=yes`. Use a bare `Mpv` for the observer/events tests and a `Player` for the state-listener and dispose tests. Each listener-throw test subscribes and triggers inside `runZonedGuarded`, records the uncaught zone error, awaits the returned future, and then asserts both that the sentinel is among the recorded zone errors and that delivery continued. Add tests:
    - `throwing observer listener does not stop another observer`: on a bare `Mpv`, observe `volume` twice; make the first listener throw a sentinel `StateError` when it sees 33; `setProperty('volume', 33.0)`; wait until the second listener sees 33.0; assert the sentinel is in the captured zone errors.
    - `throwing events listener does not stop observers`: on a bare `Mpv`, subscribe a listener to `mpv.events` that throws a sentinel `StateError` on `PropertyChangeEvent`; observe `volume`; `setProperty('volume', 44.0)`; wait until the observer sees 44.0; assert the sentinel is in the captured zone errors.
    - `throwing Player state listener does not stop other listeners`: add a listener to `player.volume.stream` that throws a sentinel `StateError` when it sees 55; add a recording listener; call `setVolume(55)`; wait until the recorder sees 55; assert the sentinel is in the captured zone errors.
    - `throwing dispose hook does not skip later hooks or the core`: add a first hook that throws a sentinel `StateError` and a second hook that appends to a list; `expectLater(player.dispose(), throwsA(same(sentinel)))`; assert the second hook ran and `player.mpv.isDisposed` is true.

    Keep the guarded body's own assertions failing the test: `await` the future returned by `runZonedGuarded` so an assertion error inside the body is not mistaken for the listener error, and keep the sentinel assertions outside the guarded body.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| application listener -> `Mpv._dispatch` | Arbitrary user code runs synchronously inside the isolate's event drain |
| `MpvStreamSource` -> `StreamBridge` | Host code crosses into the demuxer request path and may throw or never answer |
| repeated lifecycle -> native core | Every create/dispose pair allocates and frees a native handle |
