    Harden `Mpv._dispatch` so application listeners cannot break event delivery. For `PropertyChangeEvent`, look up the observer controller, return early when it is null or `isClosed`, and wrap `controller.add(value)` in `on Object catch` that appends the error to a new private `final List<Object> _listenerErrors`. Do the same for the `_events.add(event)` broadcast, skipping when `_events.isClosed`. Never rethrow from `_dispatch`; the wakeup loop must keep draining `mpv_wait_event`. Expose `@visibleForTesting int get listenerErrorCountForTesting => _listenerErrors.length;`. Add a comment stating that Phase 3 (OBS-02) will route these errors to `Player.errors`; do not add that routing now.

    Create `packages/mpv_kit/test/failure_injection_test.dart` with `@Tags(['failure-injection'])`, `@TestOn('vm')` and a `library;` directive, following the header convention in `mpv_test.dart`. Add helpers to create a `Player`/`Mpv` with `vo=null`, `ao=null`, `idle=yes`. Add tests:
    - `throwing observer listener does not stop another observer`: observe `volume` twice, make the first listener throw a `StateError`, set volume to 33, and wait until the second listener sees 33.0; assert `listenerErrorCountForTesting` is greater than zero.
    - `throwing events listener does not stop observers`: subscribe a throwing listener to `mpv.events`, observe `volume`, set volume to 44 and mute to true in one burst, and wait until the observer sees 44.0.
    - `throwing Player state listener does not stop other listeners`: add a throwing listener to `player.volume.stream`, add a recording listener, call `setVolume(55)`, and wait until the recorder sees 55.
    - `throwing dispose hook does not skip later hooks or the core`: add a first hook that throws a sentinel `StateError` and a second hook that appends to a list; `expectLater(player.dispose(), throwsA(same(sentinel)))`; assert the second hook ran and `player.mpv.isDisposed` is true.

    Avoid: do not catch `Error` types selectively; catch `on Object` because a listener may throw either an `Error` or an `Exception` and either must be isolated.
    Avoid: do not change `Mpv.events` or `observeProperty` signatures.
    Avoid: do not add a timeout or retry to the drain loop.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| application listener -> `Mpv._dispatch` | Arbitrary user code runs synchronously inside the isolate's event drain |
| `MpvStreamSource` -> `StreamBridge` | Host code crosses into the demuxer request path and may throw or never answer |
| repeated lifecycle -> native core | Every create/dispose pair allocates and frees a native handle |

| T-01-07 | Denial of Service | `Mpv._dispatch` / `_onWakeup` | high | mitigate | Per-listener `on Object catch` isolates a throwing listener; the drain loop continues; errors are recorded in `_listenerErrors`. |
| T-01-08 | Denial of Service | `StreamBridge` read/seek/close | high | mitigate | `on Object` mapping to mpv error codes; `shutdown()` contains throwing `close()`; failure-injection tests bound dispose at 10 s. |
