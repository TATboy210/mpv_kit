<objective>
D3D-04 与 D3D-05：让 gpu-next（libplacebo 渲染器）也能在上游 D3D11 render API 下运行，并用新的原生冒烟测试在无 GPU 的 Windows runner（WARP）上证明 gpu 与 gpu-next 两种渲染器都真的画出了正确的像素。上游 PR #17764 只实现了 `gpu`（vo_gpu + `ra_d3d11`）；gpu-next 在 D3D11 下需要我们在补丁 0004 的 libmpv gpu-next 后端里加一个分支：`ra_d3d11`（hwdec 映射需要它）与 `pl_d3d11` 共用宿主设备，宿主纹理用 `pl_d3d11_wrap` 包装——上游 `video/out/gpu_next/context.c` 的窗口版 VO 已经是同样的配对。D3DCompile 很慢，没有持久缓存时每次启动首帧都会卡顿，所以 0003 的持久 shader cache 语义（同样的 `--gpu-shader-cache`/`--gpu-shader-cache-dir` 选项与 `shader_<key>` 文件布局）要覆盖 D3D11 的 DXBC：0003 的代码在 `libmpv_vk.c` 中只能看到 Vulkan 的 pl_gpu，因此在 0004 的 D3D11 分支里让 vo_gpu_next 自己的 `cache_init`/`pl_gpu_set_cache` 挂到 pl_d3d11 上（Claude 裁量：复用上游现成的缓存实现，不复制一份）。

先做只依赖 0010 的 gpu 变体 smoke（tracer：证明 D3D11 render API 在 WARP 上端到端可用），再做 0004 分支与 gpu-next/cache 变体，最后把 smoke 接到发布层打包 bundle 上。

Purpose: 14-07 的 D3D11Backend 要上报 `d3d11 (gpu-next) on <adapter>`，前提是 libmpv 真正在 D3D11 上提供 gpu-next。
Output: render_d3d11_smoke.c、meson 测试、重生成的 0004 与 vendor 树、render_vk.h 文档、release.yml 打包 bundle 冒烟步骤。
