# Testing Patterns

**Analysis Date:** 2026-10-23

## Test Framework

**Runner:**
- `package:test` (`test: ^1.25.0`) for the pure-Dart packages: `packages/mpv_kit`, `packages/mpv_kit_libs`.
- `flutter_test` (SDK) for the plugin package: `packages/mpv_kit_video`.
- Config: `packages/mpv_kit/dart_test.yaml` declares one tag:
  ```yaml
  tags:
    format:
  ```
  There is no root test config; each package is run from its own directory.
- Native C tests use Meson + the `test()` harness: `native/tests/meson.build`.

**Assertion Library:**
- `package:matcher` matchers through `expect` / `expectLater` (bundled with `test` and `flutter_test`).
- No `mockito`, `mocktail`, `bloc_test`, `fake_async`, or golden helpers.

**Run Commands:**

```bash

# From packages/mpv_kit (needs libmpv at runtime)

dart test                                  # all tests (format tag included but self-skips)
dart test -x format                        # exclude the format matrix (CI release path)
dart test -j 1 -r expanded test/format_matrix_test.dart   # format matrix, serial
dart analyze --fatal-infos

# From packages/mpv_kit_video

flutter analyze --fatal-infos
flutter test

# From packages/mpv_kit_libs

dart analyze --fatal-infos
dart test

# Coverage (mpv_kit; CI gate)

dart pub global activate coverage
dart pub global run coverage:test_with_coverage

# Native smoke/integration tests

meson setup tests-out native/tests
meson test -C tests-out --print-errorlogs --verbose
```

**Environment required by integration tests:**
- `MPV_KIT_LIBMPV_PATH` — path to a real `libmpv` (`.so.2` / `.dylib` / `-2.dll`). Without it, libmpv-backed suites fail; the video plugin suite skips instead (see `_libmpvAvailable()`).
- `MPV_KIT_FORMAT_SAMPLES` — directory produced by `tools/make_format_samples.sh` containing samples plus `expect.tsv`; the format matrix self-skips when unset (`packages/mpv_kit/test/format_matrix_test.dart`).

## Test File Organization

**Location:**
- Tests are **flat** in each package's `test/` directory. There are no `unit/`, `widget/`, `integration/`, or `golden/` subdirectories, and no `integration_test/` directory anywhere.
- File counts: 8 in `packages/mpv_kit/test`, 2 in `packages/mpv_kit_video/test`, 1 in `packages/mpv_kit_libs/test` (~1,869 lines, ~111 tests).

**Naming:**
- `<subject>_test.dart`, one file per behavior area:
  - `models_test.dart` — pure node/parsing/value-object tests (no libmpv).
  - `mpv_test.dart` — low-level `Mpv` against real libmpv.
  - `player_test.dart` — high-level `Player` behavior.
  - `api_surface_test.dart` — remaining API + setters, each verified by reading the property back.
  - `options_test.dart`, `audio_devices_test.dart`, `stream_bridge_test.dart`, `format_matrix_test.dart`.
  - `controller_channel_test.dart`, `video_controller_test.dart` (plugin).
  - `bundle_test.dart` (bundle/tar integrity; no external deps).

**Structure:**

```
packages/
├── mpv_kit/test/          # pure-Dart unit + libmpv integration, flat
├── mpv_kit_video/test/    # Flutter platform-channel + widget tests, flat
└── mpv_kit_libs/test/     # bundle/tar unit tests, flat
native/tests/              # C11 meson tests (render_vk_smoke, stream_bridge_test)
```

## Test Structure

**Suite header convention — always present in `mpv_kit` tests:**

```dart
// Headless integration tests against a real libmpv (vo=null, ao=null).
//
// Requires libmpv: set MPV_KIT_LIBMPV_PATH or have it on the loader path.
// Media is generated by mpv itself via lavfi, so no fixture files are needed.
@TestOn('vm')
library;
```

The header states what the file proves, its runtime requirements, and any fixture strategy. `@TestOn('vm')` is used in all 8 `mpv_kit` test files.

**Grouping and lifecycle:**

```dart
void main() {
  group('Mpv', () {
    late Mpv mpv;
    setUp(
      () => mpv = Mpv.create(
        options: const {'vo': 'null', 'ao': 'null', 'idle': 'yes'},
      ),
    );
    tearDown(() => mpv.dispose());
    ...
  });
}
```

- `group` per class/area or per parser (`group('MpvTrack.fromNode')`, `group('errors')`, `group('installBundle')`).
- Resource disposal is either `tearDown(() => player.dispose())` or `addTearDown(player.dispose)` for one-off objects (`packages/mpv_kit/test/audio_devices_test.dart`, `api_surface_test.dart`).
- Temporary directories are created in `setUp`/`setUpAll` and deleted in `tearDownAll` (`packages/mpv_kit/test/player_test.dart`, `packages/mpv_kit_libs/test/bundle_test.dart`).
- Test names are full behavior sentences: `'create passes renderer and symbols, parses the result'`, `'rejects an archive whose hash does not match the pin'`, `'disposing right after enumeration does not crash'`.

**Shared in-file helpers (not a shared test library):**

```dart
Future<T> _until<T>(MpvState<T> s, bool Function(T) ok) => ok(s.value)
    ? Future.value(s.value)
    : s.stream.firstWhere(ok).timeout(const Duration(seconds: 10));
```

This helper and the `_lavfi` URI constant are duplicated verbatim in `mpv_test.dart`, `player_test.dart`, `api_surface_test.dart`, `stream_bridge_test.dart`, and `format_matrix_test.dart`. Follow that pattern rather than adding a cross-package test helper unless consolidating deliberately.

## Mocking

**Framework:** None. There are no mock libraries and no generated mocks.

**Patterns:**

*Hand-written fakes implementing interfaces* (preferred for async/transport behavior):

```dart
/// Answers every call after a delay, like a network source.
final class _SlowSource implements MpvStreamSource {
  _SlowSource(this._inner);
  final MpvMemoryStreamSource _inner;
  var reads = 0;

  @override
  Future<Uint8List> read(int maxBytes) async {
    reads++;
    await Future<void>.delayed(const Duration(milliseconds: 2));
    return _inner.read(maxBytes);
  }
  ...
}

/// Never answers reads.
final class _StuckSource implements MpvStreamSource {
  @override
  Future<Uint8List> read(int maxBytes) => Completer<Uint8List>().future;
  ...
}
```

See `packages/mpv_kit/test/stream_bridge_test.dart`.

*Fake Flutter platform channel* for the plugin (`packages/mpv_kit_video/test/controller_channel_test.dart`):

```dart
TestWidgetsFlutterBinding.ensureInitialized();
final messenger =
    TestDefaultBinaryMessengerBinding.instance.defaultBinaryMessenger;
messenger.setMockMethodCallHandler(_channel, (call) async {
  calls.add(call);
  if (call.method == 'create') {
    return {'textureId': 7, 'backend': 'vulkan', 'reason': 'vulkan (x)'};
  }
  return null;
});
```

Native → Dart events are simulated by sending a real encoded method call:

```dart
Future<void> nativeEvent(String kind, [String message = '']) =>
    messenger.handlePlatformMessage(
      _channel.name,
      _channel.codec.encodeMethodCall(MethodCall('event', {
        'textureId': 7, 'kind': kind, 'message': message,
      })),
      (_) {},
    );
```

**What to mock:**
- Native method channels when testing Dart-side routing (`mpv_kit_video`).
- Stream sources for failure/blocking scenarios (never-answering, slow).
- Environment and OS via parameters instead of process state: `MpvVideoController.defaultShaderCacheDir(os: 'linux', environment: {...})` (`packages/mpv_kit_video/test/video_controller_test.dart`).

**What NOT to mock:**
- libmpv itself. Integration tests use a real headless libmpv with `vo=null, ao=null`; media comes from lavfi (`av://lavfi:testsrc2=...`) or a generated temp WAV.
- The tar/bundle layer. Tests construct real tar bytes and real gzip archives in-process (`packages/mpv_kit_libs/test/bundle_test.dart`).

## Fixtures and Factories

**No committed fixture media files.** Everything is generated:

*lavfi synthetic media:*

```dart
const _lavfi = 'av://lavfi:testsrc2=size=320x240:rate=30:duration=2';
await player.open(_lavfi);
```

*WAV built in-test for exact seeks:*

```dart
/// Writes [seconds] of silent 8 kHz mono 16-bit PCM as a WAV file.
File _writeSilentWav(String path, {int seconds = 3}) { ... }
```

(`packages/mpv_kit/test/player_test.dart`)

*PNG obtained without fixtures:*
`stream_bridge_test.dart` plays lavfi, takes `player.screenshotToFile(...)`, and serves the PNG bytes through a custom protocol.

*Tar archives built in-test:*

```dart
/// Builds a ustar archive; [type] '0' = file, '2' = symlink, '5' = dir.
Uint8List tar(List<(String, String, String)> entries) { ... }
String manifestFor(Map<String, String> files) => ...
```

(`packages/mpv_kit_libs/test/bundle_test.dart`)

**Location:** Temporary files/directories live under the OS temp dir with cleanup:

```dart
setUp(() => tmp = Directory.systemTemp.createTempSync('mpv_kit_libs_'));
tearDown(() => tmp.deleteSync(recursive: true));
```

**Format matrix data:** `tools/make_format_samples.sh` generates samples and `expect.tsv`; `format_matrix_test.dart` reads it and creates one test per row, grouped by codec/container expectations.

## Coverage

**Requirements:** 80% line coverage, enforced by CI **only for `packages/mpv_kit` on Linux**:

```bash
dart pub global run coverage:test_with_coverage
awk -F: '/^LF:/{a+=$2} /^LH:/{b+=$2} END{printf "::notice::mpv_kit line coverage %.1f%% (%d/%d)\n",100*b/a,b,a; if (100*b/a < 80) exit 1}' coverage/lcov.info
```

(`.github/workflows/native-verify.yml`)

- `packages/mpv_kit_video` runs `flutter test` with no coverage gate; `packages/mpv_kit_libs` runs `dart test` with no coverage gate.
- `coverage/` is gitignored (`.gitignore`), though local `packages/*/coverage/lcov.info` files exist from prior runs.
- Coverage is measured against the **headless** libmpv build; native rendering paths are covered only by the C smoke test, not by Dart coverage.

**View Coverage:**

```bash
cd packages/mpv_kit
dart pub global activate coverage
dart pub global run coverage:test_with_coverage

# then open coverage/lcov.info with any lcov reporter

```

## Test Types

**Pure unit tests (no libmpv):**
- `packages/mpv_kit/test/models_test.dart` — node parsing, enum mapping, option validation, event decoding from hand-built FFI structs, `MpvMemoryStreamSource`.
- `packages/mpv_kit_libs/test/bundle_test.dart` — tar parsing/security, manifest verification, atomic installation, target mapping.
- `packages/mpv_kit_video/test/video_controller_test.dart` — default shader-cache path logic.
- These always run, including without native dependencies.

**Integration tests against real libmpv (headless):**
- `mpv_test.dart`, `player_test.dart`, `api_surface_test.dart`, `options_test.dart`, `audio_devices_test.dart`, `stream_bridge_test.dart`, `format_matrix_test.dart`.
- Use `vo=null, ao=null` (and `idle=yes` where needed) so they run on GPU-less runners.
- This is the dominant test type for the core package; it verifies behavior by reading mpv properties back after commands (`expect(prop('playlist-count'), 3)`).

**Widget tests:**
- `packages/mpv_kit_video/test/controller_channel_test.dart` uses `testWidgets` for `MpvVideo` layout:
  ```dart
  expect(tester.getSize(find.byType(Texture)), const Size(400, 225));
  ```
  Async native work is driven with `tester.runAsync(...)` and `pumpEventQueue()`.
- No golden tests.

**End-to-end tests:** Not used. The `example/` app is built in CI (`flutter build <target> --debug`) but not driven by an `integration_test` suite.

**Native C tests (Meson):**
- `native/tests/render_vk_smoke.c` — renders one frame through `MPV_RENDER_API_TYPE_VULKAN`, reads it back, checks the pixel; exit 77 when no Vulkan device/Metal.
- `native/tests/stream_bridge_test.c` — async custom-stream bridge, including shutdown while a request is pending.
- Registered in `native/tests/meson.build` with timeouts (60 s smoke, 90 s bridge); built with `warning_level=3, werror=true`.
- CI runs them normally, under ASan+UBSan (`sanitizers` job, `detect_leaks=0`), and against packaged bundles.

## Common Patterns

**Async testing — poll state, never sleep a fixed duration:**

```dart
Future<T> _until<T>(MpvState<T> s, bool Function(T) ok) => ok(s.value)
    ? Future.value(s.value)
    : s.stream.firstWhere(ok).timeout(const Duration(seconds: 10));

final tracks = await _until(player.tracks, (t) => t.isNotEmpty);
```

The same pattern handles events and futures:

```dart
final err = player.errors.first.timeout(const Duration(seconds: 10));
await player.open('/definitely/not/a/file.mkv');
expect((await err).error, MpvError.loadingFailed);
```

**Async error assertions — `expectLater` for futures:**

```dart
await expectLater(
  mpv.commandAsync(['no-such-command']).result,
  throwsA(isA<MpvException>()),
);
```

**Matcher vocabulary used across the suite:**
`throwsA(isA<T>())`, `throwsArgumentError`, `throwsRangeError`, `returnsNormally`, `closeTo(value, tolerance)`, `same(node)`, `hasLength(n)`, `contains`/`containsAll`/`containsPair`, `anyOf`, `isNot(contains(...))`, `greaterThan`, `isNull`/`isNotNull`, `isTrue`/`isFalse`.

**Skip gating for optional native capability:**

```dart
bool _libmpvAvailable() {
  try {
    MpvLibrary.open();
    return true;
  } on MpvLibraryNotFound {
    return false;
  }
}
void main() {
  final skip = _libmpvAvailable() ? null : 'libmpv not available';
  test('...', () async { ... }, skip: skip);
}
```

Format matrix uses a self-skip at suite level:

```dart
if (manifest == null || !manifest.existsSync()) {
  test('format matrix', () {}, skip: 'MPV_KIT_FORMAT_SAMPLES not set');
  return;
}
```

**Optional-capability tags and timeouts:**

```dart
@Tags(['format'])
@Timeout(Duration(minutes: 5))
library;
```

The tag is declared in `packages/mpv_kit/dart_test.yaml`; release CI runs `dart test -x format` followed by the matrix alone with `-j 1`.

**Regression tests are named after the crash/contract they lock down:**
- `audio_devices_test.dart` documents two native crashes (CoreAudio NULL import, WASAPI hotplug after apartment teardown) and asserts the fixed behavior, including 20 create/enumerate/dispose cycles.
- `bundle_test.dart` asserts rejection of parent traversal, absolute paths, symlinks, corrupted headers, hash mismatch, missing manifest, and extra files.

**Test isolation:**
- Each test creates its own `Mpv`/`Player` in `setUp` or locally; no shared mutable state between tests.
- `dispose()` idempotency is itself tested (`player_test.dart`, `controller_channel_test.dart`).
- Temp directories are unique per test file and removed in teardown.

## CI Test Wiring

**`.github/workflows/flutter-plugin.yml`:**
- `flutter analyze --fatal-infos` for `packages/mpv_kit_video` and `example`.
- `flutter test` in `packages/mpv_kit_video`.
- Debug build of the example on Linux/Windows/macOS.
- libmpv is **not** installed: Dart suites that need it are skipped (video) or excluded (only the plugin package runs here).

**`.github/workflows/native-verify.yml`:**
- Builds libmpv on Linux x64/arm64, macOS x64/arm64, Windows x64/arm64.
- ABI audit against `tools/rea_abi_audit/expected_symbols.txt`.
- Native tests on every target; a dedicated ASan+UBSan job.
- `dart analyze --fatal-infos` and `dart test` for `mpv_kit` and `mpv_kit_libs`, with `MPV_KIT_LIBMPV_PATH` pointing at the freshly built library.
- 80% coverage gate on Linux for `mpv_kit`.
- The Dart-only jobs temporarily `sed` the workspace `pubspec.yaml` to drop Flutter members (`mpv_kit_video`, `example`) and delete their directories, because those runners have no Flutter SDK.

**`.github/workflows/release.yml`:**
- Runs native smoke tests against the packaged bundle.
- Runs `dart test -x format`, then `dart test -j 1 -r expanded test/format_matrix_test.dart` with `MPV_KIT_FORMAT_SAMPLES` generated by `tools/make_format_samples.sh`.

## Gaps and Constraints (current state)

- No `dart format` enforcement step in any workflow; style is checked only by analysis.
- Coverage threshold exists only for `mpv_kit`; `mpv_kit_libs` and `mpv_kit_video` have no numeric gate.
- No tests for the C++ renderer implementations themselves (Windows D3D11, Linux GL, macOS Metal interop); the C smoke test exercises the shared Vulkan path only.
- No golden/widget rendering assertions beyond texture sizing; the example app is compiled but not executed.
- `MPV_KIT_FORMAT_SAMPLES` matrices run only in release CI, so codec coverage is not exercised on every PR.
