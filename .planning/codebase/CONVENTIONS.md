# Coding Conventions

**Analysis Date:** 2026-10-27

## Naming Patterns

**Files:**
- Dart: `snake_case.dart`, one primary public type per file (`MpvVideoController` → `packages/mpv_kit_video/lib/src/video_controller.dart`).
- Generated Dart lives in `packages/mpv_kit/lib/src/generated/` (`options.dart`, `catalog.dart`, `option_types.dart`, `catalog_types.dart`) with a `// GENERATED by tools/gen_*.dart ... — do not edit.` header.
- Dart tests: `<subject>_test.dart` (`packages/mpv_kit/test/player_test.dart`). Integration tests: `example/integration_test/<scenario>_test.dart`; shared helpers without the suffix (`impeller_smoke_modes.dart`).
- Native tests: `native/tests/video_renderer_<kind>[_<variant>].cc` (`video_renderer_golden_sw.cc`, `video_renderer_golden_vk_retire_twice.cc`, `video_renderer_sw_hold_front_test.cc`); golden traces `native/tests/golden/<variant>.txt` matching the binary suffix.
- C++ plugin: shared `packages/mpv_kit_video/src/*.cc/.h`, platform `windows/*.cpp`, `linux/*.cc`, `macos/Classes/*.mm`.

**Functions:**
- lowerCamelCase, verb-first (`setProperty`, `tryGetProperty`, `registerStreamProtocol`, `syncDisplayRefreshRate`).
- Named factories for construction (`Mpv.create`, `Player.wrap`, `MpvTrack.fromNode`).
- Private helpers `_`-prefixed and small (`_until`, `_nonEmpty`, `_trackId`).
- C++: PascalCase methods (`AcquireFront`, `SetSize`, `SetIccProfile`, `CompositorLatency`), `snake_case()` accessors (`backend()`, `backend_reason()`), `kConstant` constants (`kWaitTimeout`, `kTrackFrom`).

**Variables:**
- Dart top-level constants are lowerCamelCase, not SCREAMING_SNAKE (`secureDefaultOptions`, `bundleTag`); private test constants `_lavfi`, `_timeout`.
- Booleans use `is`/`has` (`isDisposed`, `hasPlayer`).
- `final` locals enforced by `prefer_final_locals`.

**Types:**
- Public classes are `final class` unless designed for extension; namespaces are `abstract final class` (`MpvLibrary`, `MpvOptions`); closed hierarchies `sealed` (`MpvEventData`) with exhaustive `switch`.
- Records for lightweight pairs: `(int, int)? _size`.
- Enums lowerCamelCase with explicit wire names where native differs (`MpvVideoRenderer.gpuNext('gpu-next')`).

## Code Style

**Formatting:**
- `dart format` output: 2-space indent, 80 columns, trailing commas on multi-line lists. Not gated in CI — format before committing.
- Generated files opt out with `// ignore_for_file: lines_longer_than_80_chars`.
- C/C++: no `.clang-format`; match surrounding file (2-space in `native/tests/*.cc`, 4-space in C tests). Sections separated by `// --- Name ---------` rules.

**Linting:**
- `packages/mpv_kit/analysis_options.yaml`, `packages/mpv_kit_libs/analysis_options.yaml`: `package:lints/recommended.yaml`. `packages/mpv_kit_video/analysis_options.yaml`, `example/analysis_options.yaml`: `package:flutter_lints/flutter.yaml`.
- All enable `strict-casts`, `strict-inference`, `strict-raw-types` and rules `prefer_final_locals`, `prefer_single_quotes`, `unawaited_futures`, `cancel_subscriptions`, `close_sinks`, `always_declare_return_types`.
- CI runs `dart analyze --fatal-infos` / `flutter analyze --fatal-infos`.
- `packages/mpv_kit/test/api_freeze_test.dart` is excluded from analysis (uses `dart:mirrors`); keep it compile-clean manually.
- No `// ignore:` in hand-written library code. Benchmark/integration tests use `// ignore_for_file: avoid_print` because stdout is their report channel.
- Native: `native/tests/meson.build` sets `c_std=c11`, `cpp_std=c++17`, `warning_level=3`, `werror=true`; the renderer library under test builds at `warning_level=1`, vendored volk at `0`.

## Import Organization

**Order:**
1. `dart:` imports
2. `package:` imports
3. Relative imports of sibling `src/` files

**Path Aliases:**
- None. Inside a package use relative imports (`import '../core/errors.dart';`); tests, hooks and the example import `package:mpv_kit/mpv_kit.dart` / `package:mpv_kit_video/mpv_kit_video.dart` barrels only.

## Error Handling

**Patterns:**
- libmpv negative codes → `MpvException(code, message, operation:)` (`packages/mpv_kit/lib/src/core/errors.dart`).
- Absent features tolerated by error code only (`tryGetProperty` returns null for `propertyUnavailable`/`propertyNotFound`; `Mpv.create` tolerates `optionNotFound`).
- Library load failure → `MpvLibraryNotFound` listing every attempted path (`packages/mpv_kit/lib/src/ffi/library.dart`).
- Cleanup-then-rethrow uses `on Object { ...; rethrow; }`; no bare `catch (e)` in `packages/*/lib`.
- Stream bridge maps source failures to mpv error codes rather than throwing across FFI (`packages/mpv_kit/lib/src/core/stream_bridge.dart`).
- Native renderer reports failures as typed events (`render_error`, `device_lost`, `software_fallback`) via the event callback, never crashes the app (`packages/mpv_kit_video/src/video_renderer.cc`).
- `dispose()` is idempotent and awaits every subscription/controller close.

## Logging

**Framework:** `print` only at controlled points; diagnostics travel as data.

**Patterns:**
- One creation line in `packages/mpv_kit_video/lib/src/video_controller.dart` (`mpv_kit_video: <backend> (<reason>)`).
- Expose diagnostics as streams (`Player.logs`, `Player.errors`, `MpvVideoEvent`), not log calls.
- Integration/bench tests print one machine-readable `BENCH <label> {json}` line per stage (`example/integration_test/uhd_endurance_test.dart`, `impeller_smoke_test.dart`).
- Native tests print prefixed status lines (`GOLDEN skip:`, `HOLD ok scenarios=<n>`, `HOLD invariant ...`).

## Comments

**When to Comment:**
- Explain why, with evidence (measured numbers, source references like `client.h:278`, ADR/plan IDs like `CR-01`, `ADR 0004 Decision 4`, `VERIFY-01`).
- Every test file starts with a header comment: what it proves, how to run it, required env vars, exit-code/skip semantics.
- Comments in `packages/mpv_kit/lib/src/core/` and `player/` are often Chinese; others English. Match the file; do not translate.
- No `TODO`/`FIXME` markers in `packages/` or `native/tests/`; keep it that way.

**JSDoc/TSDoc:**
- Every public Dart class/member carries `///` docs; libraries start with a doc comment and `library;`.

## Function Design

**Size:** Small, single purpose; extract helpers aggressively. Expression bodies for one-liners.

**Parameters:** Named parameters with defaults for optional values; validate at the boundary and fail fast. Test seams use `@visibleForTesting` instead of public API (public API is frozen — see `packages/mpv_kit/test/api_freeze_test.dart`).

**Return Values:** Primitives, records, immutable models; collections returned as `Map.unmodifiable`/copies. All waits bounded with `.timeout(...)`; ignored futures wrapped in `unawaited(...)`.

## Module Design

**Exports:** One barrel per package (`packages/mpv_kit/lib/mpv_kit.dart`, `packages/mpv_kit_video/lib/mpv_kit_video.dart` re-exports `mpv_kit`, `packages/mpv_kit_libs/lib/mpv_kit_libs.dart`) with `hide` for internals.

**Barrel Files:** None inside `lib/src/`. Do not hand-edit generated files; regenerate via `tools/gen_catalog.dart`, `tools/gen_options.dart`, `tools/pin_bundles.dart`.

**Vendored code:** `native/mpv/` is the upstream mpv tree (third-party, ~960 files); change it only through patches in `native/patches/` (drift checked by `tools/check_patches.sh`). `packages/mpv_kit_video/third_party/` (Vulkan-Headers, volk) is vendored unmodified.
