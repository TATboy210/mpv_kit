## Provenance gap (recorded, not resolved)

The shipped DLL was built at engine revision `cf636b1dfb`. That revision is
NOT resolvable in the `flutter/engine` GitHub repository (API returns
`422 No commit found`). Consequently the chain

`shipped DLL` ↔ `tag-tree source at 3.47.8`

is unverified at the revision level. It is instead supported by:

- identical anchor-string counts between the 3.47.6 and 3.47.8 DLLs;
- an identical import table between the two DLLs;
- byte-identical engine source files at tags 3.47.6 and 3.47.8 for every file
  this phase reasons about.

This gap is stated again in the report provenance section; behaviour
conclusions are not at risk, but the binary↔source link is one hop short.
