    - Test (tamper): appending one line to a vendor file (e.g. native/mpv/MPV_VERSION) makes the script exit 1 naming the file; restoring it makes the run pass again.
  </behavior>
  <action>
    Write `tools/check_patches.sh` (bash, `set -euo pipefail`):
    1. Read the base commit from `native/mpv/MPV_VERSION` (strip a leading `v`, keep the full `g<sha>` form → extract the 40-hex sha after `g`; MPV_VERSION holds `v0.41.0-1113-gfd9265a905` so the sha is `fd9265a905...` — resolve the full sha via `git ls-remote` against the mpv repo? No: the short sha must resolve inside the cloned repo; use `git fetch origin <short-sha>` which accepts shortened shas).
    2. `mktemp -d`; `git clone --filter=blob:none --no-checkout https://github.com/mpv-player/mpv.git "$tmp/mpv"`; `git -C "$tmp/mpv" fetch origin "<short-sha>"` then `git -C "$tmp/mpv" checkout --detach FETCH_HEAD` (blobless clone keeps this cheap).
    3. Apply each `native/patches/0*.patch` in sorted order with `patch -p1 --forward -d "$tmp/mpv"` (UPSTREAM.md: git apply is unreliable for these; GNU patch is the canonical applier).
    4. Compare: `diff -r --exclude=.git --exclude=.gitignore "$tmp/mpv" native/mpv` — any difference: print it and exit 1 with a message naming base commit and patch set. Any exclusion beyond `.git`/`.gitignore` must be added as an explicit, commented variable.
    5. Cleanup the temp dir in an EXIT trap. Print `PATCH-DRIFT OK base=<sha> patches=7`.
    Then prove both behavior cases locally (clean pass; tamper MPV_VERSION → fail → restore).

    Avoid: do not use `git apply` (UPSTREAM.md documents false success on this host).
    Avoid: do not exclude any file categories beyond .git/.gitignore without an explicit in-script justification comment.
    Avoid: do not cache the clone across runs in CI (local caching is fine via a caller-provided dir if convenient, default fresh).
  </action>
