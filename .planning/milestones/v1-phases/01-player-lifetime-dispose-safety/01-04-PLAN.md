<objective>
Close the phase's one BLOCKER and the two approved low-risk lifecycle gaps in `Mpv` and `Player`.

Purpose: Verification reproduced CR-01 with real libmpv: `Mpv.dispose()` called from a synchronous `Mpv.events` listener reaches the events close while that sync broadcast controller is still firing, Dart throws `Bad state: Cannot fire new event. Controller is already firing an event`, the exception escapes `dispose()`, `_events` stays open, and `_disposed` being true makes the second `dispose()` a no-op. This directly falsifies the phase truth that `events` and every `observeProperty` stream emit `done` on dispose. The same round closes two adjacent invariant leaks: `Player.audioDevices` first read after dispose returns a state outside `_states` that never closes, and `Player._onEvent`'s end-file error branch adds to `_errors` without the `isClosed` guard its sibling branch has.

Output: a dispatch-safe controller close helper used by both `_events` and `_observers`, a reentrant-dispose regression test, a closed post-dispose `audioDevices` state, and an `isClosed`-guarded error branch.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| application listener -> `Mpv._dispatch` | Arbitrary user code runs synchronously while a broadcast controller is firing and may re-enter `dispose()` |
| `Mpv.dispose` -> controller teardown | Teardown closes controllers that may still be mid-dispatch |
| `Player.audioDevices` -> application | A lazily created state escapes after teardown and owns a listener subscription |
| `Player._onEvent` -> `_errors` | A late end-file event can arrive after the error controller is closed |

| T-01-11 | Denial of Service | `Mpv.dispose` re-entered from a synchronous `Mpv.events` listener | high | mitigate | One dispatch-safe `_closeIfOpen` helper catches the `StateError` and retries the close in `scheduleMicrotask`; both `_events` and every observer controller route through it; a regression test drives dispose from inside the listener and bounds `done` at 5 s. |
| T-01-12 | Denial of Service | `Player.audioDevices` first read after dispose | medium | mitigate | The `_disposed` branch closes the freshly created state with `unawaited(state._close())` before returning it; the state is never registered in `_states`, so no eager hotplug monitoring is added. |
