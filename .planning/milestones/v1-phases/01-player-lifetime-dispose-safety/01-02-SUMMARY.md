# Phase 01 Plan 02: Post-dispose Mpv Guard and API Freeze Summary

**Every public `Mpv` entry point now fails with a catchable `StateError` before touching the destroyed handle, and a native-entry counter proves no FFI call was entered; the `Mpv`/`Player` public surface is mechanically pinned to the pre-phase API plus two annotated test seams.**

## Accomplishments

- `Mpv._ensureAlive()` throws `StateError('Mpv has been disposed')` before any `bindings.*` call and increments `_nativeEntries` only past that check.
- All 31 public handle-reaching members are guarded at their first statement: `initialize`, `clientName`, `clientId`, `timeNs`, `createClient`, `loadConfigFile`, `setOptionString`, `setOption`, `command`, `commandString`, `commandAsync`, `setProperty`, `setPropertyString`, `deleteProperty`, `getProperty`, `tryGetProperty`, `getPropertyString`, `setPropertyAsync`, `getPropertyAsync`, `observeProperty`, `getOptionValue`, `setOptionValue`, `registerStreamProtocol`, `requestLogMessages`, `requestEvent`, `hookAdd`, `hookContinue`, `wakeup`, `waitAsyncRequests`, `errorString`, `eventName`.
- `observeProperty.onListen` keeps the disposal check and counts its own native entry, so a stream created before dispose can never enter FFI when listened to afterwards.
- `@visibleForTesting nativeEntriesForTesting` exposes the counter. The regression test first proves the counter rises for a live `getProperty('volume')`, then asserts it is unchanged across the full 31-call post-dispose table.
- New `api_freeze_test.dart` reflects `Mpv` and `Player` with `dart:mirrors` and fails on any public addition/removal outside the baseline plus `{nativeEntriesForTesting}` / `{stateStreamsForTesting}`. It needs no libmpv.
- The pre-existing 202-line `api_surface_test.dart` was left untouched and still passes.

## Decisions Made

- `_ensureAlive()` both checks and counts, exactly as the plan specified. Composite methods therefore count twice when they delegate (e.g. `tryGetProperty` → `getProperty`). The assertion that matters — monotonic on live calls, flat across post-dispose calls — is unaffected.
- Composite methods still guard at their own entry, so the `on MpvException` handler inside `tryGetProperty` cannot swallow a post-dispose `StateError` into a `null` result.
- `observeProperty` is guarded both at construction and in `onListen`: construction-after-dispose throws immediately, while a stream built earlier fails on listen without an FFI call.
- The freeze baseline was obtained by running the test with an empty baseline (the failure reason prints sorted reflected names), then cross-checking every name against `git show <pre-01-02>:mpv.dart` and `git show HEAD:player.dart`. Reflection and sources agree: 37 pre-phase `Mpv` members and 86 pre-phase `Player` members, plus exactly the two seams.

- **Found during:** Task 2 (`dart analyze --fatal-infos`)
- **Issue:** `dart` here is the Flutter-bundled SDK, and the analyzer resolves the whole workspace (which includes the Flutter members `packages/mpv_kit_video` and `example`) against the Flutter platform, where `dart:mirrors` is unavailable — `uri_does_not_exist` plus the cascading undefined-name errors. - **Fix:** Added one documented `// ignore_for_file:` line covering the resolution errors only, in the new test file. This is the only ignore directive in hand-written code (the codebase convention normally forbids them); it is confined to the test and CI does not need it.
