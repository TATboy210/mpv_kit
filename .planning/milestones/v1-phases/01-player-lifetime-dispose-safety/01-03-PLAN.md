<objective>
Turn the lifetime guarantees into continuous, failure-driven regression coverage.

Purpose: The phase is only complete when the failure paths are exercised automatically: a throwing listener/hook, a source whose I/O throws, and 1000 create/dispose cycles. This plan proves that Dart's synchronous broadcast dispatch already isolates listener exceptions (a throwing listener surfaces as a zone error while delivery continues), adds the VERIFY-03 failure-injection suite, adds the STAB-01 soak test kept out of the default concurrent run (its RSS tripwire must see only Player-lifecycle allocations), and wires both into CI so they cannot rot or silently skip. It corrects the premise that a controller-wrapped `try/catch` can observe a listener throw: `controller.add` does not rethrow listener exceptions, so no production counter is added.

Output: `failure_injection_test.dart`, `lifecycle_test.dart`, conditional `StreamBridge` hardening, and CI/test-config wiring.
</objective>

Dart's synchronous broadcast controllers (`Mpv._events`, the `observeProperty` controllers, and `MpvState._controller`) dispatch each listener through a zone-guarded call: a throwing listener is reported as an uncaught zone error while `controller.add` returns normally. The throw therefore never propagates out of `add`, `_dispatch`/`_onWakeup` keep draining, and later listeners still receive the value. This supersedes the CONCERNS.md premise that a parse/listener exception escapes the wakeup callback: the exception is isolated by the stream, and what is missing is regression coverage, not production isolation. <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| application listener -> `Mpv._dispatch` | Arbitrary user code runs synchronously inside the isolate's event drain |
| `MpvStreamSource` -> `StreamBridge` | Host code crosses into the demuxer request path and may throw or never answer |
| repeated lifecycle -> native core | Every create/dispose pair allocates and frees a native handle |
