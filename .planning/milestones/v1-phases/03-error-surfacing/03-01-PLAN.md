<objective>
Surface Dart-side stream source failures (open/read/seek/close) on `Player.errors` with the original exception type and message preserved.

Purpose: today a throwing opener is indistinguishable from one returning null (stream_bridge.dart:225-227), a throwing read collapses to `-1` (257-259), and a throwing seek produces *nothing* observable (274-281) — the Phase 1 review pinned "containment is the contract; the error code belongs to Phase 3". The original exception never survives: callers see only the generic mpv `END_FILE` error, if anything.

Output: an error-report callback chain (bridge → Mpv → Player.errors), additive `onError` wiring on `registerStreamProtocol`, the WR-02 stream-source contract amendment, and regression tests in the existing failure-injection suite.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app stream source -> bridge | User source code runs inside mpv's request handling; its exceptions decide playback fate |
| bridge -> Player.errors | A new error flow into an existing public stream; must not fabricate or mask mpv errors |
| consumer -> report callback | The Player-installed consumer may itself throw while reporting |

| T-03-02 | Denial of Service | reporting callback failure | medium | mitigate | `_report` wraps the consumer in try/catch. |
| T-03-03 | Repudiation | silent seek failures | medium | mitigate | Seek failures surface with operation context; playback-continues semantics documented. |
| T-03-04 | Denial of Service | teardown-time reports | low | mitigate | isClosed guard; shutdown-branch containment preserved. |
