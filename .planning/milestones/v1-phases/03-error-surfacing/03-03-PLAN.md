<objective>
Make the create-time renderer fallback reasons honest: a failed D3D11 device creation or an absent Metal device names its actual cause (including the HRESULT where applicable) instead of the generic "platform has no Vulkan interop".

Purpose: `windows/d3d11_interop.cpp:28-31` ignores the `D3D11CreateDevice` HRESULT, so a device-creation failure silently falls back to software with a misleading reason (CONCERNS.md:212-219; OBS-03), and `macos/Classes/metal_interop.mm:29-31` sets `metal_ok_ = false` with no reason at all. The create-response `reason` and the Dart-synthesized `softwareFallback` event are the existing delivery channels — they only need truthful input.

Output: an `Interop::interopReason()` hook, Windows/MacOS probe reason plumbing, a null-device guard in `CreateImage`, and a Windows compile check.
</objective>
