<objective>
Make `MpvVideoController` dispose/resize concurrency-safe, prove repeated create/dispose leaks nothing, and close the IN-05 deferred finding (concurrent `Player.dispose()`).

Purpose: `MpvVideoController.dispose` (video_controller.dart:370-377) has no try/finally — a throwing dispose channel call leaves `_events` open forever, and the idempotency flag is already set so a retry cannot repair it. `setSize`/`setIccProfile` check `_disposed` before awaiting, so a call in flight when dispose wins the race surfaces an uncaught async error from `MpvVideo._requestSize`'s `unawaited(...)` (mpv_video.dart:61,65). `Player.dispose` (player.dart:640-679) has no shared future: a second concurrent caller returns immediately while teardown is still running and never observes its outcome (01-REVIEW-DISPOSITION.md IN-05). Phase 1's deferred STAB-01 clause — repeated controller create/dispose must not leak — is proven here at the Dart bookkeeping layer.

Output: hardened `video_controller.dart` dispose/resize paths, shared-future `Player.dispose`, and interleaving/soak/concurrency regression tests.
</objective>
