<objective>
Make `MpvVideoController.create` atomic: validate the platform response before trusting it, and roll back every installed resource when any step after the native creation fails.

Purpose: `create` currently trusts the platform map (`result['textureId']! as int` at video_controller.dart:179) and has no rollback — a malformed or newer plugin response crashes with a raw `TypeError` while the native render context, render thread and Flutter texture stay alive with no Dart handle to free them (CONCERNS.md:202-210). A failure in `_syncInitialRefreshRate` (video_controller.dart:187, uncaught `StateError` from a player disposed mid-create) likewise orphans the controller in `_live` and as a dispose hook, so a retry creates a second texture.

Output: `video_controller.dart` with strict response validation and a reverse-order rollback; regression tests in `controller_channel_test.dart`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Dart isolate -> native plugin (method channel) | The create response is untrusted data; its shape decides resource ownership |
| native render thread -> Dart | Native allocates context + texture before Dart sees the response; rollback must cross back |
| app caller -> create | The caller observes either a usable controller or one typed error, never a crash |
