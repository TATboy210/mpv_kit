<objective>
RBE-03 / RBE-04：把现有 Vulkan 与软件后端纯搬迁到统一的 `RenderBackend` 接口之后，行为逐项不变，并把 Start 的回退策略改成数据驱动的候选链。之后 Phase 13–15 的任何平台后端都只需新增一个候选项即可接入，删掉这一项即可回滚。

设计取舍（为「尽可能小的改动」）：**不新增 .cc 文件**——接口与工厂声明放在新头文件 `src/render_backend.h`，`SoftwareBackend` 实现在 video_renderer.cc 的匿名命名空间，`VulkanRenderBackend` 实现在 vulkan_backend.cc 的匿名命名空间（它包装已在那里的 `VulkanContext`）。这样 Windows/Linux CMake、macOS 的 unity 文件与 golden 的 meson 源码列表都不必改动，每个搬迁提交只碰 `src/` 下的 2–4 个文件。

接口方法以 ROADMAP 列出的生命周期为准：`Create`（首次调用时初始化设备，再创建 render context）、`AllocTargets`、`FrameFor`、`Render`、`Wait`、`BindThread`/`UnbindThread`（Vulkan 与软件为 no-op，为 Phase 15 的 GL 预留）、`Release`（先于设备释放 render context）、析构（最后释放设备）；另有 `wire_name()`、`frame_kind()`、`pipelined()`、`device_name()`、`RendererName()`、`FreeRetired()`、`device_failed()` 辅助。

每个任务都是一次纯搬迁提交：golden 冻结文件字节不变、常量计数不变、CI 全绿。搬迁中发现的任何问题记录下来，在本计划之后单独提交（Pitfall 11）。

**Flagged assumption（RBE-04 edge probe）：** 本阶段没有 `-SPEC.md`，确定性 edge probe 对 RBE-04 返回 `unclassified / unresolved`。本计划只证明 golden、常量审计与 CI 覆盖到的「行为不变」；RTX 4060 上 4K 30 分钟与 harness 重跑的对照属于 12-12，**不得**用「backstop」自动标记为已覆盖。该假设在 SUMMARY 中原样保留。

Output: `render_backend.h`、两个后端实现、候选链、常量审计脚本。
</objective>
