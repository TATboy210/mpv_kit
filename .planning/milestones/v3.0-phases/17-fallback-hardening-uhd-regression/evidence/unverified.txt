# Phase 17 未验证清单（17-05）。格式：项目=… 状态=未验证|延后 原因=… 能证明它的环境=…
# 本阶段的真机层只有一台 RTX 4060 笔记本（Windows 11，驱动 617.42）；托管层只有 llvmpipe、WARP 和 Apple Silicon VM 上的 MoltenVK，它们都是软件或虚拟设备，其结果不是真 GPU 的结论。
# 已证明的部分见 final-audit.txt 的 id= 行；本文件只列没有被证明、证明不充分或被延后的项目。
项目=真实驱动上的设备丢失与 TDR 序列（D3D11 DXGI_ERROR_DEVICE_REMOVED、Vulkan VK_ERROR_DEVICE_LOST 的真实触发） 状态=未验证 原因=故障注入只在 HRESULT 层（d3d11_device_lost_test）与 fake 后端（video_renderer_fault_test）；没有在真实驱动上触发过设备丢失，驱动重置后的恢复行为和事件顺序从未被观测 能证明它的环境=RTX 4060（或其他 GPU）上人为触发 TDR（如 TdrDelay 缩短加重负载）或拔出 eGPU 的用户会话
项目=Linux GL（opengl 后端）上的设备丢失 状态=未验证 原因=opengl 后端没有创建鲁棒 context（无 reset notification），设备丢失在 GL 路径上不可观测，也没有注入；故障注入 golden 只覆盖 d3d11 与 vulkan 两种 fake 后端 能证明它的环境=带 GL_ARB_robustness 的真实 Linux GPU，且后端先实现 reset 通知
项目=Linux 真实 GPU 上的显存曲线（opengl、vulkan 后端的 100 轮 soak） 状态=未验证 原因=ubuntu runner 只有 llvmpipe，纹理存储在 malloc 内存里，hosted 的 opengl soak 只证明进程 RSS 在 MALLOC_ARENA_MAX=1 下平稳；没有 Linux GPU，真实显存曲线从未被采样 能证明它的环境=带 Intel、AMD 或 NVIDIA GPU 的 Linux 桌面（X11 与 Wayland 各一次），运行 backend_soak_test 并采样 GPU 显存
项目=opengl soak 的 RSS 规则对小于约 0.9 MiB 每轮的泄漏的灵敏度 状态=未验证 原因=调试会话中带 0.9 MiB 每轮的故意泄漏时，规则在 4 次 soak 中 3 次报 growth、1 次报 flat（+22.0，规则自身 35 对 32 MiB 的设计余量）；更小的泄漏没有测过，规则不是对所有泄漏都灵敏 能证明它的环境=更多次带不同大小故意泄漏的 hosted soak，或真实 GPU 的显存曲线
项目=macOS 真机（Apple GPU，非 VM）上的矩阵格子（vulkan 经 MoltenVK、software） 状态=未验证 原因=矩阵只在 GitHub 的 macos-15 Apple Silicon VM 上跑，设备为 Apple Paravirtual device via MoltenVK，并且用的是固定的 bundle libmpv；没有 Apple 真机 能证明它的环境=真实 Mac（Apple Silicon 与 Intel 各一台更好）
项目=macOS 分支 libmpv 的 Vulkan 应用内路径 状态=未验证 原因=已登记的开放待办（macOS branch-libmpv Vulkan in-app crash）；hosted macOS 只用固定 bundle 的 libmpv，分支构建的 libmpv 在应用内走 Vulkan 的路径没有验证，崩溃未解决 能证明它的环境=真实 Mac 上用分支 libmpv 构建的示例应用
项目=arm64 Windows 与 arm64 Linux 上的真实插件矩阵 状态=未验证 原因=integration-test 只在 ubuntu-24.04、windows-2025（x64）与 macos-15 上运行；arm64 的 Windows 与 Linux 只跑原生测试（含故障注入 golden）与构建，没有运行强制后端矩阵或真实插件测试 能证明它的环境=Windows arm64 真机（如 Snapdragon X）与 Linux arm64 桌面
项目=AMD、Intel、其他 NVIDIA GPU 与 GTX 960 笔记本上的 VER-04（4K 1800 s 与 100 轮 soak 的显存曲线） 状态=未验证 原因=只在 RTX 4060 笔记本上运行；其他厂商与世代的显存行为、帧丢弃和 d3d11 或 vulkan 的差异从未被本项目执行；GTX 960 笔记本（14-10）的 FIFO 数据来自 Phase 14，不是 Phase 17 的门禁 能证明它的环境=对应 GPU 的 Windows 机器，用 rtx_run.sh 的同一套命令
