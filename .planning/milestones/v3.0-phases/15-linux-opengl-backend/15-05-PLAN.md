**FLIP_Y 的确定规则（写进 SUMMARY）：** Vulkan 图像的内存首行是图像顶部。`D-ORIENT=upright` 表示 Flutter 把 GL 纹理内存首行显示为顶部，于是 OpenGL 后端需要「首行为顶部」，FLIP_Y 取 `D-FLIP-MPV` 中的值；`D-ORIENT=flipped` 表示现有 Linux Vulkan 路径是倒置的（现有缺陷：记录为待办，本阶段不修），OpenGL 后端仍以 upright 为目标，FLIP_Y 取相反值；`D-ORIENT=unknown` 时按 `D-FLUTTER-ORIGIN`（top-left → 取 `D-FLIP-MPV` 的值；bottom-left → 取相反值；unknown → 停止上报）。

**create 期绑定：** `IMPLICATION=helper-thread` 或 `platform-thread-ok` 时都使用「后端自己的短命线程」实现 `RunBound`——它与平台线程当时的 EGL/GDK 状态无关，也不触碰 Flutter 在平台线程上的 context；`IMPLICATION=blocked` 时不执行本计划，以 blocking 上报。

       - `RendererName`：与 Vulkan 后端同一规则——`render_context_get_info(MPV_RENDER_PARAM_VULKAN_RENDERER)` 读取 mpv 实际构建的渲染器，失败为 `unknown renderer`（它在 RunBound 内、context 为当前时被调用）。`wire_name` 为 `"opengl"`；`frame_kind` 为 `Backend::kVulkan`（共享 GPU 图像，注释说明该枚举早于非 Vulkan 的 GPU 后端，插件据此选择 FlTextureGL）；`pipelined` 为 true；`device_failed`、`device_name` 返回设备状态。
       - `AllocTargets(count, w, h, keep_slot, error)`：先释放上一个 retired 代；检查 `GL_MAX_TEXTURE_SIZE`；把当前代退役——只有 `keep_slot` 的槽位进入 retired（它可能还是屏幕上的 retired front），其余槽位立即释放（发布门已经等过它们的 fence）；（重新）分配私有纹理与 FBO；分配 count 个槽位：`GL_RGBA8` 导出纹理（Flutter 只接受 RGBA8）、FBO（检查完整性）、`eglCreateImageKHR(display, context, EGL_GL_TEXTURE_2D_KHR, 导出纹理名, {EGL_IMAGE_PRESERVED_KHR, EGL_TRUE, EGL_NONE})`、一个新的 `GlInterop::Image`（`egl_image`、`egl_display`、width、height）。任何一步失败：释放本次分配的一切与刚退役的槽位（与 Vulkan 路径相同：失败后什么也不留，引擎随后清掉 retired front），设置 `*error` 并返回 false。
       - 释放一个槽位（渲染线程，context 为当前）：销毁未等待的 fence、删除 FBO 与导出纹理、`interop->Bury(image)`（Flutter 侧纹理与 EGLImage 由 populate 中的 graveyard 释放）。`FreeRetired` 释放 retired 代；`FrameFor(slot)` 返回该槽位的 `Image*` 作为 `TargetView::platform`。
       - `Render(api, ctx, slot, w, h)`：mpv 渲染进私有 FBO（`mpv_opengl_fbo{fbo, w, h, GL_RGBA8}` + FLIP_Y 常量）；失败直接返回错误码；成功后把私有 FBO 用 `glBlitFramebuffer` 拷进该槽位的 FBO（同尺寸、GL_NEAREST），把读/写 framebuffer 绑定恢复为 0，`eglCreateSyncKHR(EGL_SYNC_FENCE_KHR)` 存入该槽位（替换并销毁旧的），`glFlush`；fence 创建失败时退化为 `glFinish`（注释：设备初始化已要求 fence 扩展，这只是异常兜底）。
       - `Wait(slot)`：没有待等待的 fence 时 kOk；`eglClientWaitSyncKHR(display, sync, EGL_SYNC_FLUSH_COMMANDS_BIT_KHR, kSyncTimeoutNs)`：满足则销毁并 kOk；超时返回 kTimeout 且保留 fence（下一次 Wait 继续等）；EGL_FALSE 销毁并返回 kTimeout（没有鲁棒 context，无法区分设备丢失——注释写明该行为未在真驱动上验证）。
       - `Release(api, ctx)`（渲染线程，绑定中）：`api.render_context_free(ctx)`，然后释放全部槽位、retired 代、私有纹理与 FBO。析构（平台线程，context 不再在任何线程上为当前）：`eglDestroyContext`；调试构建断言此时已没有 GL 对象。
       - 在 Render、AllocTargets、FreeRetired、Release 中加调试断言：`eglGetCurrentContext()` 等于本后端的 context。
