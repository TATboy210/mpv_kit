### Linux consumer-path evidence (WR-03), stated plainly

Does the Linux evidence prove that a consumer's Linux app gets OpenGL? Partly.

What it proves: the exact pinned `libmpv.so.2` (sha256 `5d1ee622...`, from the verified archive, with its 17-library closure checked against MANIFEST.txt) loaded and rendered forced `opengl` on the ubuntu-24.04 runner, with zero render errors, a correct orientation and a working second controller. So the pinned Linux bundle does contain a working OpenGL libmpv, which is what INT-2 said was missing.

What it does not prove: that `flutter build linux` puts that closure into `bundle/lib/`, that `libmpv.so.2` resolves there by default name through the runner's RUNPATH, and that the new host `libEGL.so.1` dependency resolves in that location.
