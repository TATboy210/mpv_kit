<objective>
Fix the stale-stamp defect in the `mpv_kit_libs` build hook (`packages/mpv_kit_libs/hook/build.dart:76`) test-first, in its own commit, per locked decision D-07.

Today the pinned branch of the hook returns `sharedLibrariesIn(extracted)` whenever `{target}.ok` holds the pinned sha. If the extracted directory was removed and the stamp survived, that list is empty, the hook emits no code asset, and `MpvLibrary` silently falls back to `MPV_KIT_LIBMPV_PATH` or a system libmpv. This happened on this host (`docs/perf/fallback-uhd-regression.md:222`: the local `v0.1.0-dev.3` lib directory is empty under a valid stamp).

D-07, verbatim intent: honour the stamp only if the extracted `lib` directory exists and is non-empty, and fail loudly when the resulting library list is empty. Write the test first so it fails against the HEAD logic, then make it pass.

Design (Claude's discretion, recorded here): the pinned branch moves into `bundle.dart` as `resolvePinnedBundle` so the full scenario (stamp, cache dir, archive reuse, reinstall, stamp rewrite) is unit-testable with a fake fetch closure and the existing tar helpers. The hook keeps its sources and order; only the two D-07 behaviours change. The bundle itself is unaffected (`release.yml` deletes `packages/mpv_kit_libs` before its Dart tests), so this commit is independent of the release and of the tag.

Scope note (D-07): the fix covers only the pinned-release cache. The `libmpv_bundle` user-define branch stays as it is and stays trusted by path: a local directory is verified against its MANIFEST.txt when one exists, a local archive is not checked against a pin, and neither gets the stamp or empty-list checks. This is deliberate, since that branch is the user's explicit override and is not cached under a stamp. The SUMMARY repeats this scope note.

Purpose: a "pinned bundle only" run can no longer silently load something else because of a stale cache (evidence quality for the Phase 17.1 RTX check and for every consumer).
Output: one local commit (not pushed; Plan 03 pushes it), plus the RED evidence log.
</objective>
