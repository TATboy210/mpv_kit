# Phase 17.1 Plan 01: Stale bundle stamp fix (D-07) Summary

**The mpv_kit_libs build hook no longer trusts a `{target}.ok` stamp over a missing or empty `lib/`: it reinstalls from the sha256-verified cached archive (or re-downloads), and an installed pinned bundle without shared libraries now fails the build with `BundleIntegrityException`.**

## Performance

- **Duration:** about 25 min
- **Tasks:** 2 (1 tracer, 1 auto), both TDD
- **Files:** 4 product files + 1 evidence log

## Accomplishments

- Moved the pinned branch of `hook/build.dart` (old lines 72-84) into `resolvePinnedBundle({cache, target, pinnedSha256, fetch})` in `bundle.dart`; the hook now delegates with `fetch: (archive) => download(bundleUrl(target), archive)`.
- Stamp honoured only when `sharedLibrariesIn(extracted)` is non-empty, otherwise the archive is re-hashed against the pin (reinstall) or fetched again.
- Empty pinned bundle after install: `BundleIntegrityException` mentioning `no shared libraries under lib/` and the archive path, thrown before the stamp is written.
- One CHANGELOG bullet in `0.1.0-dev.4` describing both behaviours.
