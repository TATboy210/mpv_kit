## Warnings

### WR-01: Stamp is trusted when any shared library remains, so a partial extraction silently ships without libmpv

**File:** `packages/mpv_kit_libs/lib/src/bundle.dart:161-168`
**Issue:** The fix reinstalls only when `sharedLibrariesIn(extracted)` is empty. Suppose an external clean, antivirus quarantine or interrupted delete removes `lib/libmpv-2.dll` (or `libmpv.so.2` / `libmpv.2.dylib`) but leaves any dependency library behind:
- hooks_runner sees a changed asset file and re-runs the hook;
- the stamp still matches and `cached.isNotEmpty` is true;
- the hook emits the remaining dependencies without libmpv, and the build succeeds.

At runtime `MpvLibrary.open` then fails with `MpvLibraryNotFound`. This is the "silently bundling no libmpv" class that the CHANGELOG says is now fixed, and the new tests cover only the "directory gone" and "lib/ empty" cases.
**Fix:** Trust the stamp only when every `lib/` shared library that `MANIFEST.txt` lists still exists. An existence check is enough; no re-hashing is needed:
```dart
if (stamp.existsSync() && stamp.readAsStringSync() == pinnedSha256) {
  final manifest = File('${extracted.path}/MANIFEST.txt');
  if (manifest.existsSync()) {
    final expected = parseManifest(manifest.readAsStringSync()).keys
        .where((p) => p.startsWith('lib/') &&
            !p.substring(4).contains('/') &&
            isSharedLibrary(p))
        .toList();
    final complete = expected.isNotEmpty &&
        expected.every((p) => File('${extracted.path}/$p').existsSync());
    if (complete) return sharedLibrariesIn(extracted);
  }
}
```
Add a test where the stamp matches and `lib/` keeps one dependency but not `libmpv.so.2`. It should reinstall without calling `fetch`.

### WR-02: Identity tool step 3 hard-codes `sha256sum` although the tool has a `shasum` fallback

**File:** `tools/pinned_bundle_identity.sh:83-84`
**Issue:** `sha256_of` (lines 58-64) falls back to `shasum -a 256` because `sha256sum` may be missing, and the usage text lists macOS targets (`macos-arm64`). Step 3 still calls `sha256sum -c --quiet` directly and sends stderr to `/dev/null`. On a host without GNU `sha256sum` (stock macOS without coreutils), "command not found" becomes `reason=extracted bundle differs from MANIFEST.txt`. That is a false integrity failure with a misleading reason, and it hides the real problem.
**Fix:** Pick the checker the same way `sha256_of` does:
```bash
if command -v sha256sum >/dev/null 2>&1; then check=(sha256sum -c --quiet)
else check=(shasum -a 256 -c --quiet); fi
(cd "$dir" && "${check[@]}" MANIFEST.txt >/dev/null 2>&1) ||
  fail "extracted bundle differs from MANIFEST.txt"
```
Alternatively, check up front that a checker exists and fail with `reason=no sha256 tool`.

### WR-03: Linux pinned-only cell (INT-2) does not test the path consumers use

**File:** `.github/workflows/flutter-plugin.yml:132-142`
**Issue:**
- The Windows cell unsets `MPV_KIT_LIBMPV_PATH` and checks the app's copies (`app_copy=same`), so it follows the consumer load path.
- The Linux cell keeps `MPV_KIT_LIBMPV_PATH` pointed at the hook cache (`$cache/linux-x64/lib/libmpv.so.2`) and runs the identity tool without `APP_LIB_DIR`, so the result is `app_copy=skipped`.

As a result, nothing in this workflow shows that a consumer's Linux app works:
- that `build/linux/x64/debug/bundle/lib/` carries the full pinned closure;
- that `libmpv.so.2` loads there by default name through the runner's `$ORIGIN/lib` RUNPATH;
- that the new host `libEGL.so.1` dependency resolves there.

These are exactly the 0.1.0-dev.4 Linux changes that consumers will hit. The INT-2 claim ("the pinned bundle alone carries the Linux OpenGL backend") holds only for the explicit-path load.
**Fix:** Mirror INT-1:
```yaml
run: |
  unset MPV_KIT_LIBMPV_PATH
  xvfb-run -a flutter test integration_test/texture_probe_test.dart -d linux
  bash ../tools/pinned_bundle_identity.sh linux-x64 build/linux/x64/debug/bundle/lib
```
Alternatively, keep the current run and add a second, consumer-path run.

### IN-01: Package list was folded onto one line, and the comment still describes a "third line"

**File:** `.github/workflows/flutter-plugin.yml:40-46`
**Issue:** The new packages (`xvfb libegl-dev ...`) were appended to the `libvulkan1` line after a run of spaces instead of going on their own `\`-continued line. apt accepts this, but the comment "The third line is the runtime of the pinned-only opengl probe" now describes a line that does not exist.

### IN-02: `resolvePinnedBundle` builds paths with a doubled separator

**File:** `packages/mpv_kit_libs/lib/src/bundle.dart:158-160`, `packages/mpv_kit_libs/hook/build.dart:73-75`
**Issue:** The hook passes `Directory.fromUri(...resolve('$bundleTag/'))`, whose `.path` ends with a separator. `'${cache.path}/libmpv-...'` then produces `.../v0.1.0-dev.4//libmpv-linux-x64.tar.gz`, and on Windows `...\v0.1.0-dev.4\/windows-x64`. The emitted asset URIs carry `//` too. The OS tolerates this, but the tests only use a cache without the trailing slash, so the real hook shape is untested. The code before the refactor used `cache.resolve(...)`.
**Fix:** Use `cache.uri.resolve('libmpv-$target.tar.gz')` / `cache.uri.resolve('$target/')` with `File.fromUri` / `Directory.fromUri`, or strip trailing separators from `cache.path` once.

### IN-03: Thread-local owner pointer can match a later `Instance` at a reused address

**File:** `packages/mpv_kit_video/windows/mpv_kit_video_plugin.cpp:79-85, 390-395`
**Issue:** `t_bound_owner` keeps the address of an `Instance` after that instance is disposed. A new `Instance` allocated at the same address would take that stale sample into its first `binds=` window. This is log only and never dereferenced, so it is safe, but the comment says another instance's sample is always dropped.
**Fix:** Clear `t_bound_owner` / `t_descriptor_owner` when `Describe` sees `inst->dead`, or tag samples with `inst->texture_id` instead of the address.

### IN-04: Client-API guard no longer identifies the branch libmpv; no positive identity check replaces it

**File:** `example/integration_test/real_plugin_test.dart:164-176`, `.github/workflows/native-verify.yml:400`
**Issue:** Both builds now report client API 2.6, so `MPV_KIT_EXPECT_LIBMPV_API: '2.6'` cannot tell the staged branch build from the pinned bundle. The comment relies on `MpvLibrary`'s strict loading, which is correct today. A regression in that strictness would now pass this step silently.
**Fix:** When `MPV_KIT_LIBMPV_PATH` is set, also assert `MpvLibrary.resolvedPath == Platform.environment['MPV_KIT_LIBMPV_PATH']`. This uses the existing OBS-04 seam and adds no new API.

### IN-05: Locate step picks the hook bundle with `find | head -1`

**File:** `.github/workflows/flutter-plugin.yml:78`
**Issue:** The search covers every directory under `.../mpv_kit_libs/build`: other tags, `local-<target>/`, and `.staging-*` left by an interrupted install. Which match comes first is unordered. A fresh CI checkout has only `v0.1.0-dev.4/`, so this is not a CI bug today. Since the identity tool already derives the cache directory from `bundleTag`, the locate step could do the same.
**Fix:** Search `.dart_tool/hooks_runner/shared/mpv_kit_libs/build/$(sed -n "s/^const bundleTag = '\([^']*\)';.*/\1/p" packages/mpv_kit_libs/lib/src/bundles.dart)/` only.

### IN-06: Identity tool parses `bundles.dart` with a line-shape regex

**File:** `tools/pinned_bundle_identity.sh:41`
**Issue:** The pin lines are 84-86 columns long. If `dart format` is run over `bundles.dart`, it may split `'<target>':` and the hash onto two lines, and the tool would then fail with `no pin for target`. The failure is loud rather than silent, but it is a fragile coupling to formatting.
**Fix:** Keep the regex but tolerate a split entry, for example by joining lines with `tr -d '\n'` before matching. Alternatively, read the pin through `dart run` on a tiny script that imports `bundles.dart`.

### IN-07: Missing `resolvePinnedBundle` cases in the tests

**File:** `packages/mpv_kit_libs/test/bundle_test.dart:243-356`
**Issue:** Three cases are not tested:
- a stamp holding a different (older) pin while libraries are present: it must reinstall, not reuse;
- the partial `lib/` case from WR-01;
- a `fetch` that writes a wrong archive: it must throw `BundleIntegrityException` and write no stamp.
**Fix:** Add the three tests.
