<objective>
HWD-01：`Player` 的默认 hwdec 从一份全平台共用的列表改为按平台的有序列表，零拷贝候选在前，作为行为变更写入文档；用户显式 `hwdec` 仍优先。

为什么要改（mpv 列表语义，研究 1.2 与 `native/mpv/video/decode/vd_lavc.c` 271-316 行）：列表按序尝试；非 copy 条目在当前 ra 上没有 interop 时被跳过（不会拷回）；`-copy` 条目用独立设备，总能建成，所以一旦排在零拷贝条目之前就会抢先拷回；`auto-safe` 是白名单，内部把非 copy 排在 copy 之前。现在的默认值把 `d3d11va-copy` 写在 `auto-safe` 之前：D3D11 后端上它抢在 `d3d11va` 零拷贝之前被选中——这正是 HWD-02 的前置问题。macOS 上列表首项 `vulkan` 会注册 interop（MoltenVK）却解不了码，白白多一轮回落（研究 Pitfall 2、A7）；Linux 上 `auto-safe` 已经把 `vaapi` 排在 `vaapi-copy` 之前，显式写出 `vaapi` 只是让顺序可见，Linux 真正的行为变化来自 HWD-03（16-03/16-04 让 vaapi interop 能加载）。

一个检查点（Task 1）：默认列表是公开行为，一旦随发布出现就是用户依赖的默认值，所以先问；决策依据是 16-01 的 hosted spike（evidence/hwdec-spike.txt）与研究。`d3d11va-zero-copy` 按研究 2.2 建议保持 mpv 默认（no）：默认路径已是零 CPU 往返；`yes` 的边缘 padding 风险直接威胁 HWD-02「无绿帧/黑帧」；16-06 在 RTX 4060 上做 no/yes 对照，只记录数据。

平台分支放在库内部的新文件里，不从 barrel 导出、不加 Player 成员（API 冻结，api_freeze_test 用反射钉住 Player/Mpv 成员集合）。

Purpose: SC1；HWD-02 的默认路径前提（d3d11va 排在 d3d11va-copy 之前）。
Output: 决策记录、`hwdec_defaults.dart` 与两份测试、Player 接线、示例改用默认值、README/ARCHITECTURE-diagrams/ADR 0006/CHANGELOG。
</objective>
