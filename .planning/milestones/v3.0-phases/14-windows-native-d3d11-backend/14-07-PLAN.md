<objective>
D3D-06：`D3D11Backend`。每个控制器在 Flutter 的适配器上建自己的 `ID3D11Device`，mpv 经上游 D3D11 render API（0010）与 gpu-next 的 D3D11 分支（0004）直接渲染进 KMT 共享的 BGRA8 纹理环，纹理经现有 `GpuSurfaceTexture`（DxgiSharedHandle）交给 Flutter；每帧在 `ID3D11Fence`（回落 `D3D11_QUERY_EVENT`）完成后才发布。mpv_kit 自己的链路全程不经 ANGLE/EGL（Flutter 引擎内部用 ANGLE 打开我们的句柄不在控制范围内，ADR 0003）；正因为消费侧仍然没有 fence，隔离期保持 4。

接入方式完全沿用 Phase 12 的数据化候选链：`D3D11Interop::CreateBackend("d3d11")` 返回新后端，`D3D11Interop::BackendCandidates` 返回 Windows 链。本计划的链是切换前的形态：渲染器质量优先，同一档内 Vulkan 在前（vulkan/gpu-next → d3d11/gpu-next → vulkan/gpu → d3d11/gpu → software）。这样 RTX 4060 上 auto 的结果与 Phase 12 完全相同，而没有可用 Vulkan 的机器（hosted runner、GTX 960 + 核显笔记本）由 d3d11 代替软件渲染；把 Windows auto 改为 D3D11 在前是 14-11 的独立提交，需用户确认（Claude 裁量：中间形态遵守 ADR 0004 Decision 5「同档内 API 偏好在切换前不变」，回滚只需删掉两项候选）。

设计分支来自 14-01 的实测（evidence/spikes.txt）：`gate fence=` 决定 runner 上跑的是 fence 还是 query 路径（两条都实现，调试开关强制另一条以覆盖）；`gate video_support=` 决定是否必须实现去掉 VIDEO_SUPPORT 的重试（实现总是存在，日志记录是否触发）；`gate typed_uav=… decision=no-uav` 决定纹理不加 UAV 绑定；`gate max_texture2d=` 决定尺寸上限。
