<objective>
D3D-07：D3D11 设备移除映射为 `device_lost` 事件且进程不崩溃；D3D11 创建失败时按候选链回退并在 reason 中写明原因。

设备移除无法在 D3D11 上按需真实触发（没有公开 API；`dxcap -forcetdr` 会让整个系统 TDR，Flutter 自己的 ANGLE 设备也会被重置），因此在调试构建中提供一个注入接缝：只替换 `GetDeviceRemovedReason` 的 HRESULT 来源，走与真实移除相同的映射函数（Claude 裁量；记录为「模拟在 HRESULT 层，未诱发真实 TDR」）。回退逻辑本身是 Phase 12 的通用引擎，但这是它第一次面对平台提供的后端（`Interop::CreateBackend`），因此用一个平台无关的 fake 测试（新文件，不动冻结的 golden）把交错候选、设备失败传播、强制 API 与 device_lost 发射固定下来；真实硬件上「d3d11 失败 → Vulkan」在 14-11 切换后于 RTX 4060 证明。

Purpose: 失败路径可见且可恢复，满足 ROADMAP 成功标准 4。
Output: 注入接缝、设备丢失/创建失败的真实插件测试与 CI 接线、chain golden 测试、日志与文档的 API 中性化。

推送：scratch-first（`ci/14-lost`）；feat 只推绿。提交纪律同 14-01。
</objective>
