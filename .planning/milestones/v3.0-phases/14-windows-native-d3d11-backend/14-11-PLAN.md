<objective>
D3D-08：把 Windows 的 auto 链改为 d3d11/gpu-next → vulkan/gpu-next → d3d11/gpu → vulkan/gpu → software。这是用户可见的默认行为变更（每个 Windows 应用的默认后端从 Vulkan 变为 D3D11），ROADMAP 规定它必须是独立、可单独回滚的提交，并且只在 CI 与 RTX 4060 均绿之后合入。ADR 0004 Decision 5 的前提已满足：gpu-next 已在 D3D11 上运行（14-06），所以 D3D11 在同档内优先不会降低渲染器质量。

切换由用户裁决（单向门：发布后改变所有 Windows 应用的默认后端；之后再改回同样是可见的行为变更）。切换提交按 scratch-first 先在 `ci/14-switch` 上 CI 全绿，并在 RTX 4060 上用该提交的构建证明切换后的 auto、`MPV_KIT_VIDEO_API=vulkan` 仍可强制旧路径且结果与 Phase 12 基线一致、以及真实硬件上「D3D11 创建失败 → Vulkan」，然后才 cherry-pick 到 feat。最后做阶段收口审计、清理 scratch 分支，并把「发布并固定一个含 D3D11 后端的 bundle」记为待办——发布节点不在本阶段范围内（PROJECT.md：用户明确不着急发布），在此之前通过 mpv_kit_libs 拿到的固定 bundle（v0.1.0-dev.3）不含 D3D11 render API，插件会以 `d3d11/… unavailable: mpv_render_context_create: …` 的 trail 正常回落到 Vulkan。

Purpose: 完成 Phase 14 的最后一步并收口。

推送：遵守 push-authorization.txt；切换提交在 feat 上只推绿。提交纪律同 14-01。
