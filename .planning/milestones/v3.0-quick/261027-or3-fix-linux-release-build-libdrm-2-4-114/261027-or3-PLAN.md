<objective>
Fix the Linux release build (release.yml linux-x64 / linux-arm64). Vendored mpv (upstream commit 4bed99f6a, 2026-03-28) requires libdrm >= 2.4.114, but the ubuntu:22.04 release container, which sets the glibc 2.35 baseline, ships libdrm 2.4.113. This follows research option (b), the user's locked choice. A new downstream patch `0012-drm-build-against-libdrm-2.4.113.patch` lowers the meson floor to 2.4.113. It also replaces the only three 2.4.114-only libdrm calls (all in `native/mpv/video/out/vo_drm.c`) with static `drmIoctl` shims identical to libdrm 2.4.114's own bodies. DRM stays `-Ddrm=enabled` and VA-API keeps going through DRM render nodes. A new release.yml step proves that libmpv.so.2 resolves against the 2.4.113 container libdrm.

Purpose: unblock Phase 14 plan 14-03 Task 2 (its release gate cannot pass while both linux jobs fail at `meson setup`, run 40476764990). The fix also closes a latent defect. libdrm has no ELF symbol versioning, so a libmpv built against a newer libdrm would carry plain undefined references. Those would make `dlopen` fail, or crash later, on 2.4.113 hosts.

Output: patch 0012 applied to the vendored tree (PATCH-DRIFT byte-identical), an UPSTREAM.md record, the release.yml floor guard, patch-count updates in the Phase 14 plans, scratch-then-feat CI evidence.
