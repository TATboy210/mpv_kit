# 261025-rkd: Fix 0006 stream bridge native bugs (cancel-after-close UAF, open leak, seek desync)

**Status: Tasks 1-2 already drafted in the working tree (uncommitted) during the
interrupted first run — review them, then do Task 3.**

Verified facts:
- `free_stream()` runs `s->close` then `talloc_free(s)`; `p->cancel` (talloc child
  of the stream) stays linked to the parent with `cb=bridge_cancel, ctx=cookie`
  until `cancel_destroy`, but `bridge_close` has already `free()`d the cookie.
  `mp_cancel_set_cb` takes the slave lock and callbacks run under that lock, so
  detaching serialises with an in-flight callback.
- `bridge_open` returned `MPV_ERROR_NOMEM` after the host had opened its side:
  the source leaked until shutdown and mpv logged "unknown error".
- `bridge_seek` returned any `>= 0` as success; Dart `MpvMemoryStreamSource.seek`
  clamps to `[0, len]`, so an out-of-range seek silently desynchronised mpv.

## Task 1 (drafted): native fixes
- `stream/stream_cb.c s_close`: `if (p->cancel) mp_cancel_set_cb(p->cancel, NULL, NULL);`
  before `close_fn` (upstream file; the bridge is the first `cancel_fn` user, so
  the hunk belongs to 0006).
- `player/stream_bridge.c` (CRLF file): extract `notify_close(reg, id)` from
  `bridge_close`; on calloc failure call it and return `MPV_ERROR_LOADING_FAILED`;
  seek returns `MPV_ERROR_GENERIC` when `pos != offset`.

## Task 2 (drafted): tests in native/tests/stream_bridge_test.c
- opens == closes after playback (`closes_balanced()` polls <= 5 s; `closes`
  is read under `host_lock`, no longer `volatile`).
- `rejectbridge://` (host replies id -1) -> END_FILE reason ERROR, not loaded.
- 25x `loadfile membridge://` + immediate `stop` -> exercises the close/cancel
  race (UAF caught by the ASan job), closes balanced afterwards.

## Review revisions (2026-10-25, plan-checker pass; these are authoritative and supersede any conflicting text above)
- Test id budget: `MAX_STREAMS` is 32 (ids 1..31, stream_bridge_test.c:139)
  and ids are not recycled. Use 10 stop iterations, not 25, and assert the
  total OPEN count stays below the limit; do not change the limit.

  `cond_signal` (:170): a signal can be stolen by the main thread and the host
