Close the two items 17-01 deferred so the rest of Phase 17 can gate cleanly.

1. macOS verify-tier libplacebo skew. The `macos (macos-15)` job builds libmpv.2.dylib against whatever Homebrew bottles it gets (libplacebo 7.387.0 → `libplacebo.387.dylib`). The `integration-test (macos-15, ...)` job then runs its own Homebrew install and sometimes gets an older bottle (7.360.1, which has no `libplacebo.387.dylib`), so dlopen fails and the test throws `MpvLibraryNotFound` (runs 40917086107, 40922504734 attempts 1 and 2; green 40918922908, 40928914091). FFmpeg, libass, dav1d and the rest can skew the same way.

   Approach: deterministic closure staging. The build job copies the exact Homebrew dylibs that libmpv transitively links into `stage/`, rewrites every reference to `@loader_path/<leaf>`, and re-signs ad hoc. The integration job then installs nothing from Homebrew, checks the closure, and proves in process which images were loaded.

   Why not the alternative (record `brew list --versions`, then fail fast or `brew upgrade`): Homebrew cannot install a pinned old bottle, and an upgrade cannot fix a newer bottle in the integration job. That only turns the flake into a clearer red. Staging removes the second Homebrew resolution entirely.

   `dylibbundler` was also rejected. It is one more unpinned formula, and it prompts on stdin when an `@rpath` will not resolve (a hang risk on CI: 261028-otr already lost a run to a hung step). About 100 lines of auditable bash do the same job here.

   This is verify tier only. It is the macOS counterpart of the Windows job's ntldd closure stage. release.yml and native/build/* are untouched.
