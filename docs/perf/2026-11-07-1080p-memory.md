# 1080p Working Set — v0.1.1 memory gate and `hwdec-extra-frames`

**Date:** 2026-11-07
**Tree:** `8976150` (`feat/mpv-master-upgrade`)
**Machine:** Windows 11 x64, NVIDIA RTX 4060 Laptop, 32 GiB RAM
**Flutter:** 3.47.9 stable / Dart 3.13.7
**Bundles:** local `v0.1.0-dev.9` hook bundle (mpv 0.41) as a control;
`release.yml` candidate `42341558262` (mpv 0.42.0, GPL-3.0+ full, Windows x64).

## Gate

The project's v0.1.1 gate is:

> example app + local 1080p + default hardware decode + 10 minutes of stable
> playback → Windows Working Set < 250 MB.

## Method

- `example` release build, HUD visible, `MPV_KIT_EXAMPLE_AO=null`.
- Source: `13349743_1920_1080_25fps.mp4` (1920×1080 H.264, 25 fps, 17.2 s).
  A 200-entry `.m3u` repeats it for the 10-minute window; this is a proxy for a
  single long file (playlist transitions every 17.2 s). The source itself is a
  local 1080p file.
- `Get-Process` `WorkingSet64` (gate) and `PrivateMemorySize64`
  (attribution only) every 5 s for 600 s.
- Headless attribution: `Player` with `vo=null`, `ao=null`, `loop-file=inf`,
  120 s, same sample.
- Event attribution: 60 s of `videoParams`/`audioParams`/`tracks`/`playlist`/
  `chapters`/`metadata`/`position` emissions and equal-value re-emissions.

## Results

### Example app, 1080p, 10 minutes

| Bundle | Peak WS | Min WS | Mean last 5 min | Samples ≥250 MB |
|---|---:|---:|---:|---:|
| dev.9 (mpv 0.41) | 233.3 MiB | 200.4 | 225.3 | 0 / 120 |
| 0.42 GPL full, before fix | **294.1 MiB** | 259.5 | 282.9 | **120 / 120** |
| 0.42 GPL full, after fix | **234.0 MiB** | 204.7 | 225.7 | **0 / 120** |

### Headless attribution (`vo=null`, 120 s)

| Bundle | Peak RSS | `demuxer-cache-state.fw-bytes` |
|---|---:|---:|
| dev.9 (mpv 0.41) | 338.4 MiB | 0.4–10 MB |
| 0.42 GPL full | 339.2 MiB | 0.4–10 MB |
| 0.42, `hwdec-extra-frames=1` | 339.7 MiB | 0.4–10 MB |

The demuxer cache never approaches its 199.5/49.9 MiB cap, and the 0.42
headless decode/demux path is identical to dev.9. The regression is in the
Vulkan zero-copy render path.

### Render-path A/B (minimal 1080p harness, 60 s)

| Configuration | Working Set |
|---|---:|
| 0.42, `hwdec-extra-frames=auto` (default) | 254–259 MiB |
| 0.42, `hwdec-extra-frames=1` | 200–207 MiB |
| 0.42, `hwdec-extra-frames=2` | 202–213 MiB |
| 0.42, forced `Vulkan/gpu` | 268–275 MiB |

mpv 0.42 sizes the hwdec surface pool from the VO queue. With the 8-slot
Windows frame ring, `auto` adds about 50 MiB at 1080p. `gpu-next` is not the
cause: forcing `gpu` is the same.

### Event emissions (60 s)

| State | Emissions | Equal-value re-emissions |
|---|---:|---:|
| `videoParams` | 2 | 0 |
| `tracks` | 3 | 1 |
| `playlist` | 1 | 0 |
| `chapters` | 1 | 0 |
| `metadata` | 1 | 0 |
| `position` | 501 | 0 |

Model value-equality and lazy-observer work were not implemented: they are not
a meaningful memory lever for this scenario.

## Fix

`Player` now caps `hwdec-extra-frames` to `2` for video pixel area ≤ 1920×1088,
inside the existing `on_preloaded` weak-client hook (the same place as the
software-decode thread cap). Above 1080p it keeps `auto`. A value supplied
through `options`, or changed at runtime, is never overridden.

Measured effect: **294.1 → 234.0 MiB peak** over the 10-minute gate; the fix
also passes the 1080p/4K/user-override unit tests.

## Bundle strip check

The pre-strip 0.42 candidates carried removable symbol/debug sections:

| Target | Removable `.symtab` / `.debug_*` |
|---|---:|
| Linux x64 | 6.53 MiB |
| Linux arm64 | 6.90 MiB |
| macOS x64 | 1.09 MiB |
| macOS arm64 | 1.08 MiB |
| Windows x64/arm64 | 0 |

`native/build/package.sh` now strips at the packaging boundary: Linux
`strip --strip-unneeded lib/*.so*`, macOS `strip -x lib/*.dylib` before
`codesign`. The P3 rebuild (run `42348986527`) produced: Linux x64 40.38 MiB
(−6.51), Linux arm64 35.79 (−6.82), macOS x64 42.41 (−0.47), macOS arm64
37.17 (−0.47), Windows unchanged. Linux has no removable symbols left; macOS
`-x` keeps ~0.62 MiB of external symbols needed by dylib linking.

## Residual unknowns

- Linux/macOS 1080p Working Set: **not measured** (no real hardware here); do
  not infer.
- The 10-minute window uses a looping 17.2 s file, not a single long file.
- mpv #15099 (long-play leak) has no upstream fix in 0.42.0; a 10-minute run
  does not exercise it.
- The HUD/example UI is included in the gate (~20–30 MiB over a minimal
  harness), by user decision.
