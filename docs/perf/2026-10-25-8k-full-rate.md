## The fix (UHD-01): queue budgets derived from frame size, applied at runtime

v1 shipped a fixed pack (`demuxer-max-bytes=400MiB`, `demuxer-max-back-bytes=100MiB`) sized for
4K. At 8K the same byte budget holds fewer giant frames of *raw* lavfi output while total commit
(demuxer raw queue + decode pool + 633 MiB render ring + shared GPU) blew the commit limit
(v1: WER `RADAR_PRE_LEAK_64`, process death ≤ 40 s — see
[2026-10-24-uhd-endurance.md](2026-10-24-uhd-endurance.md), whose follow-up candidate #1 is
exactly this fix).

Player now derives the queue from the video parameters the moment they are known, and re-derives
on every resolution change (`packages/mpv_kit/lib/src/player/player.dart`):

```
frameBytes = w × h × 1.5                     (YUV420P planning unit)
fwd  = min(400MiB, 64 × frameBytes)          (64-frame readahead, v1 pack cap inherited)
if frameBytes ≥ 32MiB: fwd = min(fwd, 256MiB)  (giant-frame clause: bound total commit)
back = clamp(fwd / 4, 32MiB, 100MiB)
```

| Tier | Resolution | fwd / back | Note |
|------|-----------|-----------|------|
| 1080p | 1920×1080 | 199.5 MiB / 49.9 MiB | covers 1 s @ 60 fps readahead |
| 4K | 3840×2160 | 400 MiB / 100 MiB | **byte-identical to v1 — zero regression surface** |
| 8K | 7680×4320 | 256 MiB / 64 MiB | −180 MiB queue commit vs v1 |

Application rules: only fires while the current values still match the pack defaults or our own
last-applied budget (a user's explicit `setProperty` disables auto-tune permanently for that
Player); failures to apply are swallowed (tuning is best-effort, never surfaced as errors).
Formula is pinned by unit tests (`demuxerQueueBudgetForTesting` matrix) and by real-libmpv
integration tests (apply, re-tune across resolutions, user-override precedence).

## Conclusion

The queue-budget fix (UHD-01) is evidenced by the 60 s probes above, including a clean 8K
minute that v1 could never survive. **UHD-02 (30-minute 8K + 4K endurance) has no evidence**
and Phase 9 stays partial. No gate was relaxed and no run is reported as passing without a
`BENCH uhd` line. Re-running this plan requires a host with comfortable disk headroom
(≥ 5 GB is the plan's stated precondition; this host had 6.3 GB and the harness still failed)
and an uninterrupted ~65-minute exclusive window.
